# ComfyUI 模块—模型索引站（Atlas）需求文档 (PRD)

> 版本：v0.1 草案 ｜ 日期：2026-10-04 ｜ 状态：待评审
> 一句话目标：**做一个由社区维护、GitHub Action 自动部署的 ComfyUI 模块（自定义节点）↔ 所需模型 ↔ 多平台下载地址的可搜索索引站。**

---

## 1. 背景与问题

| 现状痛点 | 说明 |
|---|---|
| 装了节点 ≠ 能跑 | ComfyUI 有 **800+ 自定义节点包**，但很多节点需要单独下载模型权重（checkpoint / LoRA / ControlNet / IP-Adapter / VAE 等），否则导入工作流就是"红节点"。 |
| 模型散落各处 | 同一个节点需要的模型，可能分布在 **Hugging Face、魔搭 ModelScope、Civitai、哩布哩布** 等不同平台，新手不知道去哪下、下哪个版本。 |
| 复现工作流成本高 | 网上分享的 `.json` 工作流只含节点结构，不含模型文件；缺模型时只能靠 README、评论区、经验贴去"拼图"。 |
| 国内访问不稳定 | Hugging Face 国内慢，需要镜像（hf-mirror）；国产模型（Wan/Qwen/混元）在魔搭更快。 |

**本项目**把"节点 → 模型 → 下载地址"集中成一张可搜索、可筛选的**地图（Atlas）**，降低复现门槛。

### 1.1 术语澄清（基于调研）

- **ComfyUI modules** = 自定义节点包（custom node packs），如 `ComfyUI-IPAdapter`、`ComfyUI-ControlNet`、`ComfyUI-AnimateDiff`。
- **Atlas（参考）**：调研发现 [AtlasCloudAI/atlascloud_comfyui](https://github.com/AtlasCloudAI/atlascloud_comfyui) 是把云端模型以"节点"形式接入 ComfyUI 的项目；本项目的 **Atlas 取其"索引/地图"含义**——做一个信息黄页，而非 API 接入。若你所指的 "agent Atlas" 是另一个具体项目，请在评审时指出，我会调整定位。
- **平台简称**：HF = Hugging Face；魔搭 = ModelScope；Civitai = C 站（你提到的"西列塔"）；hf-mirror = HF 国内镜像；哩布 = LiblibAI。

### 1.2 目标 / 非目标

**目标**
- 提供一个静态站点，集中展示 ComfyUI 主流模块及其**必需模型的下载地址**，覆盖 HF / 魔搭 / Civitai 等平台。
- 支持**搜索 + 按平台 / 分类筛选**，快速定位"这个节点要去哪下模型"。
- 数据以 **JSON 维护 + GitHub PR 贡献**，GitHub Action 自动部署到 GitHub Pages。

**非目标（第一版不做）**
- ❌ 不托管模型文件本身（只放地址/直链，避免版权与带宽问题）。
- ❌ 不做 ComfyUI 运行环境 / 一键安装。
- ❌ 第一版**不自动爬取**各平台（人工 + PR 维护数据为主，后续再加爬虫/同步）。
- ❌ 不做模型评测 / 预览图生成。

## 2. 用户画像与用户故事

| 角色 | 场景 | 期望 |
|---|---|---|
| 复现工作流的新手 | 导入 `.json` 后出现红节点 | 搜节点名 → 看到要装哪些模型、去哪下 |
| 国内用户 | HF 打不开 / 慢 | 优先看到魔搭 / 哩布 / hf-mirror 等国内可达地址 |
| 资深玩家 | 想快速对比某节点的多个模型来源 | 按平台筛选，一眼看出哪个最快/最新 |
| 内容贡献者 | 发现某节点缺模型信息 | 按规范提 PR 补充数据 |

**用户故事（示例）**
- 作为*新手*，我希望*搜索节点名就能看到它需要的所有模型及下载链接*，以便*不再为红节点发愁*。
- 作为*国内用户*，我希望*每个模型都标注国内可达的镜像/平台*，以便*不用翻墙也能下载*。
- 作为*贡献者*，我希望*有明确的字段填写规范*，以便*提 PR 时不会漏填关键信息*。

## 3. 信息架构

```
首页 /
 ├─ 概览统计（节点数 / 模型数 / 已覆盖平台数）
 ├─ 搜索框（按节点名 / 模型名 / 标签）
 ├─ 筛选（分类、平台、是否官方、维护状态）
 └─ 节点卡片列表 ──► 节点详情页
        ├─ 节点信息（名称、仓库、作者、简介、分类、维护状态）
        └─ 所需模型表格（模型名 | 类型 | 平台 | 地址 | 大小 | 版本 | 备注）
```

> 第一版采用**单页应用（SPA）+ JSON 数据**，无需后端；节点"详情"可用模态框或锚点展开，降低构建复杂度。后续可拆为多页。

## 4. 数据 Schema（核心：哪些信息真正需要收集）

> 这是你最关心的部分。结论先行：**真正"必须收集"的是"节点能跑起来所需的最小信息"**；其余为锦上添花，可逐步补全，避免一开始就被数据量劝退。

### 4.1 数据结构（modules.json）

```jsonc
{
  "modules": [
    {
      "id": "comfyui-ipadapter",          // 必填：全局唯一标识（slug）
      "name": "ComfyUI-IPAdapter",         // 必填：节点包显示名
      "repo": "https://github.com/...",    // 必填：GitHub 仓库地址
      "category": "风格控制",              // 必填：分类（见 4.3）
      "author": "cubiq",                   // 可选：作者
      "official": false,                   // 可选：是否官方/权威
      "maintenance": "active",             // 可选：active|archived|unknown
      "description": "图像风格/特征迁移节点", // 可选：一句话简介
      "tags": ["ip-adapter", "风格迁移"],   // 可选：检索标签
      "models": [                          // 必填：至少 1 条；空数组表示纯逻辑节点
        {
          "name": "ip-adapter_sd15.bin",   // 必填：模型文件名/标识
          "type": "ipadapter",             // 必填：模型类型（见 4.2）
          "sources": [                     // 必填：至少一个来源
            {
              "platform": "huggingface",    // 必填：平台 key
              "url": "https://huggingface.co/...", // 必填：下载地址
              "size": "0.4 GB",            // 可选：文件大小
              "version": "v1",             // 可选：版本/变体
              "note": "需配合 clip 使用"     // 可选：备注
            },
            {
              "platform": "modelscope",
              "url": "https://modelscope.cn/...",
              "size": "0.4 GB"
            }
          ]
        }
      ]
    }
  ]
}
```

### 4.2 字段收集优先级（哪些"真正需要"）

| 字段 | 优先级 | 理由 |
|---|---|---|
| `id` / `name` / `repo` | 🔴 必填 | 没有这三项，节点无从定位 |
| `category` | 🔴 必填 | 分类筛选是核心导航 |
| `models[].name` / `type` | 🔴 必填 | "缺哪个模型"是复现关键 |
| `models[].sources[].platform` + `url` | 🔴 必填 | 本项目核心价值=下载地址 |
| `author` / `official` / `maintenance` | 🟡 建议 | 帮助判断可信度，可后补 |
| `description` / `tags` | 🟡 建议 | 提升搜索体验 |
| `size` / `version` / `note` | 🟢 可选 | 越详细越好，但非阻塞 |

> **关键判断**：一个节点条目，只要填齐"🔴 必填"五项即可上线；🟡🟢 字段随贡献者能力逐步补全。**不必等所有字段齐全才提交**——这是避免项目停滞的设计原则。

### 4.3 分类（category）枚举（初版）

`基础模型`(checkpoint/lora/vae) · `控制网络`(ControlNet/T2I-Adapter) · `风格控制`(IP-Adapter/InstantID) · `动画`(AnimateDiff) · `人脸`(FaceDetailer/InstantID) · `放大修复`(Upscale/ESRGAN) · `工作流增强`(Impact-Pack/Manager) · `视频`(Wan/Kling/FramePack) · `其他`

### 4.4 模型类型（type）枚举（初版）

`checkpoint` · `lor a` · `vae` · `controlnet` · `ipadapter` · `clip` · `unet` · `embeddings` · `upscale` · `insightface` · `other`

### 4.5 平台（platform）枚举

`huggingface` · `modelscope`(魔搭) · `civitai`(C站) · `hf-mirror`(HF镜像) · `liblibai`(哩布) · `tensorart` · `seaart` · `replicate` · `github-release` · `kaggle` · `other`

## 5. 模型平台对比（调研结果）

| 平台 | 定位 | 国内可达 | 适合模型类型 | 需登录 | 备注 |
|---|---|---|---|---|---|
| **Hugging Face** | 全球最大开源模型库（AI 的 GitHub） | 慢（需镜像） | 全品类，官方第一发布地 | 部分 | 模型卡片/版本最全；国内用 `hf-mirror.com` |
| **魔搭 ModelScope** | 阿里运营，中文生态 | ✅ 快 | 国产大模型、扩散模型 | 否 | Wan/Qwen/混元首发；国内直连 |
| **Civitai（C站）** | AI 绘画社区（C 站） | 中 | LoRA/风格/角色模型 | 部分文件 | 示例图、触发词、base model 标注全 |
| **hf-mirror** | HF 国内镜像 | ✅ 快 | 同 HF | 否 | 路径与 HF 一致，国内下载首选 |
| **哩布哩布 LiblibAI** | 国内 AI 创作社区 | ✅ 快 | 绘画/LoRA | 部分需会员 | 部分模型加密/需客户端 |
| **Tensor.Art** | AI 艺术模型中心 | 中 | SD 模型/LoRA | 否 | 社交画廊，免费额度 |
| **SeaArt AI** | 精选 AI 模型 | 中 | 绘画模型 | 否 | 教程+SEO 强，目录较小 |
| **Replicate** | API 调用/Serverless | 中 | 全品类（云端跑） | 否 | 不下载文件，调 API |
| **Roboflow** | 计算机视觉 | 中 | CV 数据集/YOLO 模型 | 否 | 偏训练/标注 |
| **Kaggle Datasets** | 数据集平台 | 中 | 数据集/部分模型 | 否 | 数据集为主 |
| **OpenRouter / Together AI** | LLM API 聚合 | 中 | 仅 LLM（API） | 否 | 不下载权重，统一 API |

> 推荐**优先覆盖 HF + 魔搭 + Civitai + hf-mirror + 哩布**，这五个解决 90% 的 ComfyUI 模型获取需求。

## 6. 技术架构

```
GitHub 仓库
 ├─ data/modules.json        # 数据源（人工/PR 维护）
 ├─ index.html               # 站点入口
 ├─ assets/
 │   ├─ styles.css
 │   └─ app.js               # 读取 JSON → 渲染列表/搜索/筛选
 ├─ scripts/validate.py      # 部署前 JSON 结构与必填项校验
 ├─ .github/workflows/deploy.yml  # push main → 校验 → 部署 Pages
 └─ README.md                # 用途 + 贡献指南
```

- **托管**：GitHub Pages（无需服务器，零成本）。
- **构建**：纯静态，无需打包工具；GitHub Action 在部署前跑 `validate.py` 校验 JSON，防止脏数据上线。
- **可扩展性**：后续可加 `scripts/crawl.py` 从 ComfyUI Registry / 各平台补充数据；当前先人工维护。

## 8. 风险与待确认问题

1. **"agent Atlas" 的具体指向**：我按"索引/地图式展示"理解。若你指某个具体项目（如 AtlasCloud 或别的开源站），请指明，我会校准定位与参考设计。
2. **数据初始来源**：建议 P0/P1 以**人工整理高频节点 + 社区 PR** 起步；是否要一开始就上爬虫，请确认。
3. **版权/合规**：站点只放**公开下载地址直链**，不托管模型文件；Civitai 部分文件需登录/会员，链接以"跳转平台"形式给出，规避合规风险。
4. **国内可达性标注**：建议每个 `source` 标注是否需要登录 / 是否国内直连，帮助国内用户。
